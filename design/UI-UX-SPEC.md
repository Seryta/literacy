## 1. 产品定位与目标用户

### 1.1 目标用户（第一约束）

**用户是还不认识字的成年中老年人**（如产品负责人的母亲），以及所有有同样需要的家庭。

> 核心约束一句话：**用户不认识字。一切设计以此为前提。**

### 1.2 由此推出的三条铁律

1. **语音是主交互通道**——用户不会打字、读不懂文字，操作靠"说"，信息靠"听"。
2. **极简，减少选择负担**——不认识字就会紧张，东西多就不知道该点哪个。每屏只呈现少数大而明确的操作。
3. **界面上的字必须能"读出来"**——页面上的字会被语音说出来给用户听（点读 / 自动朗读），文字是辅助不是主通道。

### 1.3 陪伴式定位

App 不是被动工具，而是**主动陪伴**：初始进入主动打招呼，之后按学习计划引导下一步、在适当时机提示。用户不需要主动发起操作。

## 2. 设计原则

| # | 原则 | 说明 |
|---|------|------|
| P1 | 语音优先 | 语音是操作的衔接，不是传统点击；能语音完成的不要求点击（"继续"可以说，不用点） |
| P2 | 极简卡片式 | 首页/主要页面用大卡片，一张卡只做一件事；东西少，不紧张 |
| P3 | 全面点读 | 页面上**所有显示性文字**点击即朗读（点哪读哪）；**按钮带喇叭图标后缀**（点喇叭读按钮作用）；关键场景进入时自动朗读 |
| P4 | 我们主导 | 默认路径清晰：开局学自己的名字（认识与写）；推荐字、想学的字由语音询问，不默认堆在页面 |
| P5 | 页面差异化 | 不是所有页面都一样：首页（卡片导航）/ 引导（对话）/ 学习页（米字格教学）骨架各异 |
| P6 | 适老放大 | 大字号、大按钮（≥60dp 主操作）、高对比、大触控目标 |
| P7 | 不吓唬用户 | 技术报错不暴露（"API Key"、"AI 未连接"等对用户如天书），改为温和引导（"请让家人帮忙设置"） |
| P8 | 场景克制 | 有场景感/温度（黑板、卡片、卡通角色），但不堆砌——用户最终倾向简单卡片式，场景元素服务于清晰而非装饰 |

## 3. 视觉设计规范

### 3.1 现代化方向

参照 **Windows / iOS 设计规则**：
- 分层材质（surfaceContainer 从背景逐级抬升）
- 大圆角、柔和阴影
- 图标化、规范导航（设置独立右上角按钮）
- 大留白、清晰层次

### 3.2 配色（暖琥珀 · 书香）

- 主色：暖琥珀橙（`#B45309`），辅助墨绿（`#4E6E58`）
- 背景：米白纸感（`#FDF8F0`），护眼不刺眼
- 文字 vs 背景对比度全部 ≥ 4.5:1（WCAG AA），照顾视力下降
- ⏳ 深色模式缺失（老人普遍畏光，是实际需求，待实现）

### 3.3 字体排版与适老放大配置

- 大字排版：正文 ≥17sp、按钮 18sp、标题 24sp+、核心汉字 88sp（**默认档位：大**）
- **适老放大可配置**（不是写死）：
  - 提供字号档位（标准 / 大 / 特大），默认"大"
  - **设置页手动调控**（设置 → 字体大小）
  - **语音调节**：说"字再大一点/字小一点"直接调档 ⏳
  - **感知系统 fontScale**：用户手机本身可能已放大（系统设置），App 档位叠加时不得溢出/裁切——档位基于系统字号等比，或检测系统已放大时自动降档 ⏳
- ⏳ 高 fontScale 验证缺失（现为固定字号，未配置化）

### 3.4 形状与尺寸

- 大圆角（卡片 20-28dp）、主按钮 60dp 高、触控目标 ≥56dp
- 底部安全区：悬浮吉祥物 + 系统导航条留位

### 3.5 卡通角色（吉祥物）

- **代码绘制扁平卡通**（禁止 emoji 充当角色形象——太简陋）
- 风格：古怪而亲和（机器人/小章鱼/小恐龙/小团子 4 形象，**默认"机器人"**）
- 元素：粗描边 + 高光 + 腮红，大眼睛
- 角色选择：纵向列表（从上到下，说"第几个"）
- 用户认可的形象气质：古怪亲和，不一定局限于"老师"

## 4. 语音交互设计规范（核心）

### 4.1 语音是主操作，不是辅助

- 引导阶段：**进来就自动语音交互，不需要点击"说话"按钮**
- 学习页（主场景）：进入即自动监听，说话直接进教学
- 首页：进来自动听；**初始进入问一次**"今天想学什么"，之后**不反复问**（靠默认学习计划自动推进，用户主动说才偏离）
- 页面**不应出现"点击说话"按钮**——那是给"会操作手机的人"的设计
- **全程自动监听**：引导/学习/首页进入即自动听，无需任何手势触发（不教用户"长按/按住"）；宠物状态（待机/聆听/说话）随语音状态**自动变化**，不由用户手动切换

### 4.2 实时对话体验

- 边说边显示字幕（partial results 实时转写）
- 用户开口可打断机器人朗读（barge-in）
- 识别间隙尽量短（响应快）
- ⚠️ 已知风险：常开麦克风 + TTS 朗读的回声（真机 P0 验证项；依赖设备 AEC）

### 4.3 语音控制范围

- 首页：说"学我的名字" / "想学一个字" / "复习" / "打开设置" / "我想学家"（直接学该字）
- 学习页：说"帮助 / 跳过 / 暂停 / 继续 / 结束 / 下一阶段 / 下一字"控制操作；其余说话进教学对话
- **语音调字号**：说"字再大一点 / 字小一点"调节适老档位 ⏳
- ⏳ 长尾未覆盖（设置保存/选角色等），目标"能控制所有操作"

### 4.4 悬浮吉祥物

- 所有非引导页面右下角常驻（可拖拽避让、浮动动画、气泡提示、录音态）
- ⏳ "自己动避免遮挡"目前靠手动拖拽，自动避让未实现
- ⏳ "到对应位置提示"目前只有气泡文案，角色移动提示未实现

### 4.5 点读与朗读（用户确认方案：①点哪读哪 + ②按钮喇叭后缀 + ③关键场景自动朗读）

**目标：用户不认识字，页面上的任何内容都要能被读出来。**

#### ① 显示性文字：点哪读哪

- 所有**纯展示文字**（标题、段落、提示、卡片内容）点击即朗读整段
- 统一封装 `ReadableText` 组件（Text + clickable + TTS），逐页替换
- 点击区域 = 文字块整体（易点中，不要求精确）
- 与可点击卡片共存：卡片本体点击 = 读卡片内容；卡片内文字单独点击 = 读该段

#### ② 按钮：喇叭图标后缀

- 每个按钮本体点击 = **执行操作**
- 按钮右侧小喇叭图标（🔊 小号、色调淡、不抢主按钮）点击 = **读按钮作用说明**
  （如"开始学习——从认识、会写自己的名字开始"）
- 统一封装 `ButtonWithReadOut` 组件

#### ③ 关键场景自动朗读（克制使用）

- 首页**初始进入**：机器人主动读"今天想学什么"
- 学习页教学语自动朗读
- 引导流程关键步骤自动读
- **不扩展到所有页面**（每次进页都读会打扰）

#### 引导演示（让用户知道"字能点"）

- 首次引导中加入演示：机器人教"点一下这里的字，我就会读给你听"
- ⏳ 待实现

#### 朗读反馈

- 朗读时文字高亮/轻微放大（正在读哪段，用户知道在读什么）⏳ 待实现
- TTS 失败降级：静默（文字始终可见，不阻断）

## 5. 首次引导流程（onboarding）

全程自动语音（无需点击"说话"）。**语音包、AI 配置、宠物选择为必过项（不可跳过）；仅姓名可跳过（建档可推迟）。**

```
① 协议确认（合规要求）：家人代为阅读《用户服务协议》《隐私说明》并双勾选，才解锁下一步；
   "不同意，暂不使用"退出
② 语音包准备（❌不可跳过）：
   - 检测 → 已就绪：直接继续
   - 未就绪：下载（进度清晰，建议 Wi-Fi），支持暂停/继续下载（暂停仅停下载动作，
     无"稍后再下"跳走出口）；下完自动解锁"下载完成 · 继续"
   - 下载失败：明确提示"请检查网络/Wi-Fi"，【重试】按钮，不提供跳过
③ 配置 AI 老师（❌不可跳过）：家人协助填服务商/Key/模型，仅一个"配置好了·继续"出口；
   未配置无法进入下一步（AI 评估是核心功能，缺了不完整）
④ 语音就绪：语音包装完确认（本机离线可用，不用网络）
⑤ 选宠物（❌必选，默认机器人）：竖版 1-4（机器人/章鱼/恐龙/团子），说"第几个"或点卡片；
   无"暂时不选"出口，必须选定（宠物是全局交互角色，三态与后续页面都依赖它）
⑥ 姓名（✅可跳过）：说"我叫XX"/"建档"（自然口语 AI 判断意图）/ 家人输入
   - 跳过：机器人说"以后想录名字随时说'建档'"，直接进 ⑧
   - 不跳过：确认（"我听到的是「张建国」，对吗？"）→ 3 次未确认转输入兜底 → 进 ⑦
⑦ 名字学习计划（仅录名后）：逐字展示部件拆解 + 环形进度
⑧ 学习方式说明：教"提示一下/再读一遍/休息一下/不学了"等控制词 → 说"开始"进学习
```

要点：
- **继续/开始不需要点击**，语音说即可（引导屏保留大按钮，仅供家人代操作时用）
- 语音包 + AI 配置 + 宠物选择为必过项：语音老师、AI 评估、交互角色都依赖它们，缺一不可
- 姓名可推迟（DESIGN.md 要求），跳过不锁死，随时说"建档"补录
- 姓名采集可靠（前缀剥离、确认机制、兜底输入）
- 语音包下载失败不锁死：重试；下载完成自动切回离线（不再提供系统语音兜底——STT 双端不对称）

## 6. 页面规范

### 6.1 首页（极简卡片式）

- 顶栏：品牌（圆形"字"logo）+ **右上角独立设置按钮**
- 卡片（少而大，一张卡一件事）：
  1. **学我的名字**（默认最突出）：从认识、会写自己的名字开始
  2. **想学一个字**：说出想学的字，或让家人输入（点击展开）
  3. **复习**：今天 N 个字待复习（有队列才显示）
  4. 未建档提示卡（建档入口）
- **不在首页堆**：推荐字网格、常驻输入区（推荐字/想学的字改为语音询问）
- 初始进入时机器人主动打招呼："今天想学什么？直接说"（**仅问一次**，后续靠规划不反复问）
- 卡片点击=朗读，卡片内按钮=操作，语音说卡片名=操作

### 6.2 学习页（米字格教学）

- 顶部返回（大）+ 阶段中文标签（"认识这个字/跟着写/自己写…"）
- 核心大字 + 拼音 + 米字格 + 教学语卡片
- 操作按钮 2×2 大网格（帮助/跳过/暂停/结束；复习模式：下一阶段/结束/下一复习字）
- 输入区降级为打字辅助（"打字输入（家人可帮忙）"），不再是模拟语音
- 实时字幕（"🎤 正在说…"）+ 开口打断教学朗读

### 6.3 建档页

- 表单式（姓名 + 称呼），家人协助场景
- 大按钮、卡片化

### 6.4 设置页

- ① AI 老师配置（API Key/地址/模型，家人协助："首次使用需要由家人帮忙配置一次"；引导阶段必配，设置页可随时修改/关闭）
- ② 语音包管理（下载状态 / 重新下载 / 删除重下）⏳ 待实现
- ③ 字号档位（适老放大配置，预留）⏳ 待实现
- ④ 我的小伙伴（换角色，正式入口）⏳ 待实现（当前在 debug 区）
- ⑤ 关于与许可声明
- ⑥ 开发模式（仅 debug 构建）

## 7. 学习内容与计划（用户主导权）

### 7.1 默认路径

- **默认开局学习自己的名字（认识与写）**，不绕弯
- 文字可以点"继续"，语音要问"有没有问题"，没有就开始学习
- **初始问一次**：引导完成后的第一次进首页，机器人问"今天想学什么"，用户回答后进入学习
- **后续靠规划推进**：不再反复问——按默认学习计划自动进阶（P0 名字 → P1 家庭 → P2 数字金额 → …，CURRICULUM-DESIGN），到点提示"该学 X 了/该复习了"
- **用户主动说才偏离**：用户说"我想学X字" → 插单优先，学完回到规划
- ⏳ P1/P2 生活字包零实现（姓名完成后无默认进阶路径——"靠规划推进"目前只有 P0 姓名）

### 7.2 想学的字（用户插单）——意图 Skill 化

**用户意图做成可复用的 skill**（一次定义、重复调用）：

- `学一个字` skill：用户说"我想学X字" → 提取目标字 → 校验字库 → 插单学习（优先级高于默认计划）
  - 用户明确说出字（"学X字"）→ 直接学习
  - 用户**形容**（"门上那个字"）→ 与用户交互沟通确认具体字（⏳ 候选确认流程）
- `复习` skill：说"复习" → 进复习队列
- `调节字号` skill：说"字再大点" → 调档（见 §3.3）
- `返回` skill：说"返回/回去" → 回上一页
- 其他用户意图同理：**统一注册为 skill（结构化意图处理），可重复调用**，不散落为正则匹配
- ⏳ 现状：语音命令与教学意图各自独立匹配，统一 skill 化待重构
- ⏳ 插单队列机制（优先级覆盖默认计划）：完整课程队列待实现

### 7.3 复习

- 按遗忘曲线排期，复习优先于新学（首页复习卡引导）

## 8. 适老与无障碍

- 大字号/大按钮/高对比（见 §3）
- 语音兜底一切（不识字可用）
- ⏳ TalkBack 语义缺失（悬浮角色/进度点无 contentDescription）
- ⏳ 高 fontScale 下布局裁剪未验证
- 隐私：退后台必须停麦克风监听（老人不会自己关麦克风）

---

## 9. 禁忌清单（不要做）

1. 不要把"API Key / debug / AI 未连接"等技术术语暴露给用户
2. 不要在页面上放"点击说话"按钮（语音应自动可用）
3. 不要用 emoji 当角色形象（太简陋，要代码绘制）
4. 不要堆信息（推荐字/输入区/多区块首页——用户会紧张）
5. 不要默认把选择权交给用户（"由我们主导"，除非用户主动说）
6. 不要让技术报错 kill 体验（Keystore 异常、TTS 失败都降级不崩）

## 11. 架构一：全界面 Agent 可控 + 多层组件 Skill 化

> 用户要求：**所有界面与按钮都可语音控制，都可被 AI agent 控制**——包括界面内元素（米字格、笔画）。定义多层级的组件，形成 plugin/skill 供 agent 灵活调用。

### 11.1 目标

教学 agent（LLM）不仅能"说话"，还能**操作界面的任意元素**：切换页面、点卡片、控制米字格揭示笔画、切换描红模式等。语音与 agent 控制是同一套能力的两端（用户说 = 语音命令；agent 决策 = 工具调用）。

### 11.2 多层组件层级（从粗到细）

```
应用 → 页面（Screen）→ 卡片/区块（Card）→ 基础元素（按钮/文字/输入框）
     → 领域组件（米字格 MizigeGrid）→ 元素级（笔画/网格线/描红层）
```

每层都可被：
- **语音控制**（用户说"学我的名字"→ 点主卡）
- **Agent 工具调用**（agent 调 `navigate_screen` / `tap_card` / `mizige_reveal`）

### 11.3 Skill / Plugin 注册机制

- 每个可操作组件注册为**结构化 skill**：`{ 名称, 触发词（语音/意图）, 作用范围（哪层）, 参数, 执行动作, 可读说明（TTS 用） }`
- 例：
  - `navigate_screen`（跳转页面）
  - `start_name_learning`（学我的名字，默认路径）
  - `search_char`（想学一个字：输入/搜索卡片）
  - `start_review`（复习）
  - `mizige_set_mode`（米字格模式：看/跟写/独立写）⏳
  - `mizige_reveal_stroke`（揭示第 N 笔）⏳
  - `mizige_set_tracing`（开启浅灰描红，用户跟着描摹）⏳
  - `mizige_stroke_sequence`（按笔顺一笔一画引导）⏳
- Agent 通过工具调用表获取可用 skill 清单（随 ui_state 注入，类似 DESIGN.md §Agent 工具系统）
- ⏳ 现状：语音命令与 Agent 工具各自独立，统一 skill 注册表待重构

### 11.4 米字格/笔画的 Agent 控制（重点引导场景）

用户设想的重要引导能力：
1. **描红**：显示浅灰色字形，用户可跟随描摹（`mizige_set_tracing(true)`）
2. **笔画顺序引导**：控制揭示顺序，引导一笔一画写（`mizige_reveal_stroke(N)` + `mizige_stroke_sequence`）
3. 结合现有阶段机（INTRODUCE→RECOGNIZE→DEMONSTRATE→GUIDED_WRITE→INDEPENDENT_WRITE）：
   - DEMONSTRATE 可展示描红 + 笔顺动画 ⏳
   - GUIDED_WRITE 已支持逐笔揭示（现有 revealStrokes），可扩展为 agent 可控节奏
- 米字格数据已有（字库 SVG 笔画路径 + 中位线），渲染能力已有（MizigeGrid），缺的是 **agent 控制接口** ⏳

## 12. 架构二：自我进化与用户理解机制

> 用户要求：向 **Hermes Agent**（NousResearch，self-improving AI agent）等个人助手学习，吸收"每次自我进化 + 定期梳理 + 自动生成更新 skill + 自我纠正"能力。
> 调研来源：Hermes Agent 官方仓库（README：closed learning loop / autonomous skill creation / periodic nudges / scheduled audits / Honcho user modeling）；Claude Opus 5 系统提示词（社区公开版：memory filesystem / skills / skill-creator / 从聊天历史生成记忆）。

### 12.1 调研结论（已核实）

**Hermes Agent 可吸收的机制：**
1. **闭环学习（closed learning loop）**——任务后 agent 梳理经验，沉淀为技能/记忆
2. **复杂任务后自动创建技能（autonomous skill creation）**——不需要用户要求
3. **技能在使用中自我改进（skills self-improve during use）**——技能不是一次写成，随使用修正
4. **周期性提示维护记忆（periodic nudges）**——agent 主动想起"该整理记忆了"
5. **定时任务（scheduled automations）**——daily reports / weekly audits，自然语言定义，无人值守
6. **会话搜索 + LLM 摘要（FTS5 session search + summarization）**——跨会话回忆
7. **用户建模（Honcho dialectic user modeling）**——持续的辩证式用户理解

**Claude Opus 5 可吸收的机制：**
1. **memory filesystem**——结构化持久记忆（profile / topics / areas / people / preferences），写"未来 Claude 需要的前置上下文"，**问用户前先查记忆**，版本 token 防并发，写入有严格规则（interview 边问边写、不宣布写入成功、删除仅用户明确要求）
2. **skills 标准**——SKILL.md 最佳实践文件夹，**写代码/建文件前强制读相关 SKILL.md**，skill-creator 可创建技能
3. **从聊天历史生成记忆（generate memory from chat history）**

### 12.2 本项目的自我进化设计

**原则：用户不懂这些，不询问是否创建 skill；最多告知"以后想怎么样可以说……"。默认制定任务服务用户。**

#### 每次学习 session 后（每次进化）
session 结束（已有 `end_session` 结构化总结）→ 追加"自我进化"步骤：
- 梳理本次**难重点**（哪些字/笔画/阶段卡住，struggles 已有）
- 梳理 **agent 需改进**（本次教学哪里不好：解释不清楚/节奏太快/重复纠错）
- 记录**用户习惯**（语速偏好/何时学/喜欢哪些字/常见说法）
- 记录**被纠正的行为**（用户多次说"不对/不是这个"的地方——agent 理解偏差）
- 更新**用户模型**（记忆文件，见 12.3）
- 产出：难重点清单 + agent 改进点 → 存记忆，供下次 session 注入

#### 定期完整梳理（每周，定时任务）
- 每周自动执行（Hermes scheduled automations 模式）：
  - 汇总本周所有 session 的难重点/改进点/习惯 → **自动生成或更新 skill**（如"张阿姨对'家'的竖钩总写反，教学时先强调"——更新对应 skill/教学提示）
  - 完整梳理用户模型（理解加深、偏好变化）
  - 输出周报（存记忆，不打扰用户；必要时转为教学调整）
- ⏳ 定时执行器（WorkManager）待实现

#### 记忆结构（借鉴 Opus 5 memory filesystem）
```
/profile.md            学习者档案（姓名/称呼/初始水平/语速字号偏好）
/topics/<char>.md      每个字的学习记录（难点/错误模式/复习排期）
/areas/name-plan.md    名字学习计划进度
/preferences.md        偏好（字号档位/语速/是否默认拼音）
/agent-notes.md        agent 自我改进笔记（被纠正行为/待改进教学点）
/skills/               agent 可复用的教学 skill（难重点对策/用户特定教法）
```
- 原则：写"未来 agent 需要的前置上下文"，session 开始注入；问用户前先查记忆
- ⏳ 现有数据层（字记录/会话总结/复习排期）可作雏形，扩展为记忆文件系统 + agent 读写接口待做

#### 技能生命周期（Hermes 模式）
```
复杂任务/周梳理 → 识别可复用经验 → 自动创建 skill（不询问）
→ 使用中验证 → 效果好保留/效果差修正 → 过时移除
```

#### 自我纠正
- agent 被多次纠正的行为（用户说"不对"）→ 记录到 agent-notes → 下次 session 注入提示"上次 X 被纠正，注意 Y"
- 纠正闭环：用户纠正 → 记录 → 下次改进 → 用户不再纠正 = 成功（不再打扰）

#### 不打扰原则
- 创建/更新 skill、周梳理全部后台自动
- 用户可见的仅：教学行为变化（更懂用户了）+ 偶尔一句"以后想怎么样，可以直接说……"
